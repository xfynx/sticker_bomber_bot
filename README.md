# Sticker Bomber Bot

Телеграм-бот, который следит за сообщениями в группах и каналах и на заданные
слова устраивает обстрел стикерами: кидает фразу-предупреждение, показывает
обратный отсчёт и высыпает пачку случайных стикеров.

**Стек:** Python 3.12 · aiogram 3 · SQLite (aiosqlite) · Docker

---

## Как это работает

1. Кто-то пишет сообщение с триггерным словом.
2. Бот бросает кубик — срабатывает с вероятностью `chance` (1–100%).
3. Реплаем прилетает фраза-предупреждение из настраиваемого списка.
4. Следующим сообщением идёт таймер `💣 залп через 3…`, обновляемый раз в секунду
   через `editMessageText`. По нулям сообщение удаляется.
5. Летят `count` случайных стикеров, отправка идёт параллельно.

Стикерпаки делятся на **обычные** и **NSFW**. Флаг `/nsfw on` в чате
**переключает пул целиком**, а не расширяет его: с включённым NSFW летят только
🔞 паки, обычные не подмешиваются. По умолчанию режим выключен.

Следствие: если NSFW включён, а ни одного 🔞 пака владелец не добавил, бот
промолчит. Команда `/nsfw on` в таком случае прямо об этом предупредит.

## Запуск

### Docker (рекомендуется)

```bash
cp .env.example .env
# заполнить BOT_TOKEN и OWNER_IDS
docker compose up -d --build
docker compose logs -f
```

База лежит на именованном томе `bot-data`, так что пересборка образа ничего не теряет.
Для боевого сервера — раздел [Деплой на сервер](#деплой-на-сервер) ниже.

### Локально

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
python bot.py
```

### Переменные окружения

| Переменная         | По умолчанию       | Что делает                                        |
|--------------------|--------------------|---------------------------------------------------|
| `BOT_TOKEN`        | —                  | Токен от [@BotFather](https://t.me/BotFather)     |
| `OWNER_IDS`        | —                  | Твои user id через запятую (узнать: @userinfobot) |
| `DB_PATH`          | `data/bot.sqlite3` | Файл базы                                         |
| `DEFAULT_BURST`    | `5`                | Стикеров за триггер в новых чатах                 |
| `DEFAULT_COOLDOWN` | `5`                | Пауза между бомбёжками, сек                       |
| `DEFAULT_CHANCE`   | `100`              | Вероятность срабатывания, %                       |
| `DEFAULT_DELAY`    | `3`                | Обратный отсчёт, сек (0 — без таймера)            |
| `MAX_BURST`        | `25`               | Потолок для `/count`                              |
| `SEND_CONCURRENCY` | `8`                | Параллельных отправок                             |
| `LOG_LEVEL`        | `INFO`             | Уровень логов                                     |

## Деплой на сервер

Дальше — обычный VPS с Ubuntu 22.04/24.04 или Debian 12. Бот ходит наружу сам,
входящие порты открывать не нужно: long polling, не webhook. Хватит самой
дешёвой машины — 1 vCPU и 512 МБ памяти.

### 1. Docker

```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER   # чтобы не писать sudo перед каждой командой
newgrp docker                   # или просто перелогиниться
```

Скрипт ставит и Docker Engine, и плагин `compose`. Проверка:

```bash
docker compose version
```

### 2. Код

```bash
sudo mkdir -p /opt && cd /opt
git clone git@github.com:xfynx/sticker_bomber_bot.git
cd sticker_bomber_bot
```

Если на сервере нет SSH-ключа с доступом к репозиторию, есть два пути:
завести на GitHub **deploy key** (Settings репозитория → Deploy keys, доступ
только к одному репозиторию — для сервера правильнее личного ключа) либо
клонировать по HTTPS, раз репозиторий публичный.

### 3. Конфиг и запуск

```bash
cp .env.example .env
nano .env          # BOT_TOKEN и OWNER_IDS обязательны
docker compose up -d --build
```

Проверить, что поднялся:

```bash
docker compose ps
docker compose logs -f
```

В логах должно появиться `Запущен как @имя_бота (id=…)`. Если вместо этого
`BOT_TOKEN не задан` — контейнер не увидел `.env`, проверь, что файл лежит
рядом с `docker-compose.yml`.

### 4. Автозапуск

Отдельный systemd-юнит не нужен: в compose стоит `restart: unless-stopped`,
а сам Docker после установки уже включён в автозагрузку. Убедиться:

```bash
sudo systemctl is-enabled docker    # ожидаем "enabled"
```

После перезагрузки сервера контейнер поднимется сам. Единственный случай,
когда он не вернётся, — если ты остановил его руками через `docker compose stop`.

### 5. Обновление

```bash
cd /opt/sticker_bomber_bot
git pull
docker compose up -d --build
```

База переживает пересборку: она лежит на именованном томе `bot-data`, а не
внутри образа. Мусор от старых сборок иногда стоит подчищать:

```bash
docker image prune -f
```

### 6. Бэкап базы

Вся конфигурация — слова, паки, фразы, настройки чатов — в одном файле SQLite.
Снять копию, не останавливая бота:

```bash
docker compose exec -T bot python -c "
import sqlite3
src = sqlite3.connect('/data/bot.sqlite3')
dst = sqlite3.connect('/data/backup.sqlite3')
src.backup(dst)
dst.close(); src.close()
"
docker compose cp bot:/data/backup.sqlite3 ./backup-$(date +%F).sqlite3
```

Тут используется онлайн-бэкап SQLite: он корректно снимает копию с горячей
базы, в отличие от простого `cp` — на живой WAL-базе так можно получить битый
снимок. Утилиты `sqlite3` в образе нет (`python:3.12-slim` её не содержит),
поэтому зовём тот же механизм через модуль `sqlite3` из стандартной библиотеки.

Восстановление:

```bash
docker compose stop bot
docker compose cp ./backup-2026-08-05.sqlite3 bot:/data/bot.sqlite3
docker compose start bot
```

Раз в сутки в cron:

```bash
0 4 * * * cd /opt/sticker_bomber_bot && docker compose exec -T bot python -c "import sqlite3; s=sqlite3.connect('/data/bot.sqlite3'); d=sqlite3.connect('/data/backup.sqlite3'); s.backup(d); d.close(); s.close()"
```

### 7. Чего не делать

- **Не запускать два экземпляра с одним токеном.** Telegram отдаёт апдейты
  только одному потребителю: второй `getUpdates` выбьет первый, и боты начнут
  отбирать друг у друга сообщения с ошибкой `TerminatedByOtherGetUpdates`.
  Перед запуском на сервере останови локальный `python bot.py`.
- **Не коммитить `.env`.** Он в `.gitignore`, но токен всё равно стоит
  отозвать у @BotFather, если он куда-то утёк.
- **Не хранить базу в bind-mount на сетевой ФС.** SQLite и NFS не дружат
  из-за блокировок; именованный том на локальном диске — то, что нужно.

### Диагностика

```bash
docker compose logs --tail=100        # последние строки
docker compose restart bot            # перезапуск
docker compose down                   # остановить (том с базой остаётся)
docker compose down -v                # ⚠️ снести вместе с базой
```

Если нужно больше подробностей — поставь `LOG_LEVEL=DEBUG` в `.env` и
`docker compose up -d`. На уровне DEBUG видно, в том числе, промахи по `chance`.

## Настройка бота

### Первые шаги

1. У [@BotFather](https://t.me/BotFather) выключи Privacy Mode:
   `/mybots` → бот → *Bot Settings* → *Group Privacy* → **Turn off**.
   Без этого бот не увидит обычные сообщения в группах.
2. Добавь бота в чат и дай права на отправку сообщений
   (для каналов — право публиковать посты, для таймера ещё и удалять свои сообщения).
3. Напиши боту в личку `/start`.

### Команды владельца (только в личке)

| Команда | Что делает |
|---|---|
| `/addpack <имя\|ссылка> [nsfw]` | Добавить стикерпак. Можно просто кинуть боту стикер — он подскажет имя пака |
| `/delpack <имя>` | Удалить пак |
| `/packs` | Список паков |
| `/packkind <имя> default\|nsfw` | Сменить категорию |
| `/packtoggle <имя> on\|off` | Временно отключить пак |
| `/refresh [имя]` | Перечитать стикеры из Telegram |
| `/gwords`, `/gaddword`, `/gdelword` | Глобальные слова — работают во всех чатах |
| `/phrases` | Фразы-предупреждения |
| `/addphrase <текст>` | Добавить фразу |
| `/delphrase <номер>` | Удалить фразу |
| `/togglephrase <номер> on\|off` | Включить/выключить фразу |
| `/seedphrases`, `/clearphrases` | Стартовый набор фраз |
| `/scope <chat_id> list\|add\|del\|clear [пак]` | Ограничить чат конкретными паками |
| `/stats` | Статистика |

### Команды админов чата

Работают прямо в группе. Для каналов (где у сообщений нет автора) — в личке:
`/chats` → `/use <chat_id>`, дальше команды применяются к выбранному чату.

| Команда | Что делает |
|---|---|
| `/settings` | Текущие настройки |
| `/words` | Список слов |
| `/addword кот, доброе утро` | Добавить слова (запятая или новая строка) |
| `/delword кот` | Удалить слово |
| `/clearwords` | Очистить список |
| `/toggle on\|off` | Включить/выключить бота в чате |
| `/nsfw on\|off` | Переключить пул на 🔞 паки (обычные при этом отключаются) |
| `/count 1-25` | Стикеров за триггер |
| `/chance 1-100` | Вероятность срабатывания в процентах |
| `/delay 0-60` | Обратный отсчёт перед залпом |
| `/warn on\|off` | Фраза-предупреждение |
| `/cooldown <сек>` | Пауза между бомбёжками |
| `/reply on\|off` | Отвечать реплаем |
| `/match word\|substring` | Целые слова или подстрока |

### Демо в личке

- `/demo [1-10]` — показать, как выглядит обстрел (владельцу доступно `/demo 5 nsfw`)
- `/try <фраза>` — проверить, сработал бы триггер, не поднимая шум в чате

## Режимы поиска

- `word` (по умолчанию) — только целые слова: «кот» не сработает на «котёл»,
  но сработает на «кот!», «(кот)» и «кот-обормот».
- `substring` — совпадение в любом месте: «кот» поймает и «котёл».

Регистр не важен, zero-width символы вырезаются, так что «к‌о‌т» тоже поймается.

## Заметки по эксплуатации

- **FloodWait.** Telegram ограничивает частоту отправки. `SEND_CONCURRENCY`
  регулирует агрессивность; при `TelegramRetryAfter` бот ждёт и повторяет
  до трёх раз, ожидание дольше 30 секунд считает безнадёжным.
- **Потеря прав.** Если бота лишили права писать, он сам ставит чату
  `enabled = false`, чтобы не долбиться в закрытую дверь. Вернуть — `/toggle on`.
- **Кулдаун** проверяется после броска кубика: промах по `chance` паузу не съедает.
- **Удаление из чата** чистит его настройки, слова и скоуп паков.
